# VoiceInspect 上线准备状态

更新时间：2026-09-08

本项目当前目标是 Windows 本地 Docker 环境中的生产化内部试点，不宣称真实现场故障诊断准确率。AI 输出始终是辅助证据整理和建议，故障写入需要人工确认。

## 已落地并有自动化证据

- 本地账号、四角色权限、组织范围校验、会话持久化、退出/撤销、过期、并发会话上限和登录失败限流。
- 新建账号和管理员重置账号的首次改密标记；密码更新要求 12 位、大写、小写和数字。
- 固定全局侧边栏、诊断会话列表独立滚动、对话区独立滚动、输入区固定在诊断区底部。
- 设备、故障、知识、报告、审计和系统设置后台页面，受保护 API 在服务端校验权限。
- 文档 SHA-256、来源元数据、解析/索引失败持久化和重试；仅发布文档参与 RAG。
- 视觉结构化 Schema、证据绑定、设备类型约束和缺证据降级。
- 流式回答结束标记处理、任务详情/事件回放、单能力失败保留其他输入。
- 故障确认、分派/改派、负责人通知、逾期查询、状态事件和审计。
- SQLite Alembic 迁移、独立存活探针、Docker 非 root API、数据备份/校验恢复脚本。
- 后端自动化测试、前端 TypeScript/Vite 构建、Vitest 和 UX 静态门禁均需以本次实际命令输出为准。

## 仍需上线前人工或环境验证

- 浏览器桌面/窄屏/键盘/断线恢复截图和真实 E2E：当前自动化浏览器工具没有可用执行内核。
- 真实设备厂商手册、现场图片、20 条语音样本、四类设备视觉评测和 RAG Recall/Citation Precision：当前只有公开资料和合成/演示资产，不能替代现场验收。
- STT/VLM/TTS 模型冷启动、CPU 资源和长时间稳定性：取决于部署机器模型与运行时。
- 多进程/多副本下的登录限流、后台任务队列、外部通知、CMMS/MES/ERP、OIDC/SSO：本轮保留边界，未作为内部试点必需集成。
- 报告首期仍是同步生成接口；需要大批量导出时应接入持久化 Worker。
- 列表当前主要采用服务端数据全量加载后的前端分页；数据规模扩大前应将分页/搜索下推到 API。
- Docker 通过 host.docker.internal 访问宿主机 Ollama；若部署主机没有对应模型，健康状态会降级但文本/历史等非模型能力仍可用。

## 上线前操作清单

1. 复制 .env.example 为 .env，替换 ACCESS_TOKEN_SECRET、演示密码和允许来源；正式环境设置 SEED_DEMO_DATA=false。
2. 执行 alembic upgrade head，启动后检查 /api/v1/health/live 和 /api/v1/health。
3. 使用 scripts/provision_admin.py 创建或轮换正式系统管理员，随后禁用演示账号。
4. 导入拥有使用权的知识资料，核对来源、许可证、适用设备、版本和 SHA-256，再由知识管理员发布。
5. 执行备份、恢复和恢复后健康检查演练。
6. 用维修主管账号走完“新建→已确认→处理中→待验证→已关闭”，检查负责人、处理结果、验证依据和审计。
7. 在目标机器上完成浏览器矩阵、模型延迟、资源占用和现场样本评测后，才决定是否进入试点。

## 明确不宣称

在获得现场样本、人工标注、稳定运行数据和业务方签字前，不宣称现场诊断准确率、自动故障定责或无人值守维修决策。
